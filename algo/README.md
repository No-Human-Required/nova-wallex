# الگوریتمیک (Algorithmic) — پلتفرم ساخت و اجرای ربات معامله‌گر

برنامه‌ای جدا از موتور حساب Nova در همین مخزن: پروسه، فضای پایگاه‌داده و کانتینر جدا. کاربر با کد پیامکی وارد می‌شود، ربات می‌سازد، بک‌تست می‌گیرد، آزمایشی (کاغذی) اجرا می‌کند و پس از تأیید ادمین روی حساب صرافی خودش (فعلاً والکس) اجرای واقعی دارد. بک‌آفیس همهٔ تنظیمات، کاربران، پلن‌ها، پرداخت‌ها و تأییدها را مدیریت می‌کند.

## اجزا

| بخش | فایل | کار |
| --- | --- | --- |
| وب | `algo/main.py`، `algo/static/` | سایت عمومی، پنل کاربر، بک‌آفیس، API |
| ورود | `algo/auth.py`، `algo/sms.py` | کد ۶ رقمی با پترن IPPanel (کد `fuspysk44m9yajp`، متغیر `OTP`)، ۲ دقیقه اعتبار، ۵ تلاش، محدودیت هر شماره و هر IP |
| پرداخت | `algo/payments.py` | زرین‌پال v4؛ sandbox یا واقعی از بک‌آفیس؛ تمدید پلن فقط یک بار برای هر پرداخت تأییدشده |
| ربات | `algo/bots.py`، `algo/exchanges.py` | پارامترهای همان آزمایشگاه بک‌تست + پروفایل ریسک + فیلتر AI؛ والکس فعال، نوبیتکس «به‌زودی» |
| اجرا | `algo/executor.py`، `algo/runner.py` | یک مسیر برای آزمایشی و واقعی؛ هر ۳۰ ثانیه خروج‌ها، در بسته‌شدن هر کندل ورودها |
| AI | `algo/ai.py` | همان `AdaptiveAI` نوا با کلید پلتفرم و سهمیهٔ ماهانهٔ هر کاربر |

## قواعد ایمنی اجرای واقعی

- اجرای واقعی فقط با: کلید API تأییدشده (فقط خواندنی بررسی می‌شود)، پلنی که ربات واقعی دارد، و **تأیید ادمین**. هر تغییر تنظیمات تأیید را برمی‌دارد.
- هر سفارش پیش از ارسال با شناسهٔ یکتا ثبت می‌شود؛ پاسخ نامعلوم فقط با GET روشن می‌شود و تا وقتی سفارشی نامعلوم است، ربات سفارش تازه نمی‌فرستد. اگر ۳۰ دقیقه نامعلوم بماند، ربات مسدود می‌شود تا ادمین بررسی کند.
- ربات فقط از سرمایهٔ اختصاصی خودش خرج می‌کند و هرگز بیش از موجودی آزاد تومان حساب؛ فقط دارایی‌ای را می‌فروشد که خودش خریده است.
- فروش‌ها لیمیت قابل‌اجرا با سقف ۲٪ زیر بهترین خرید، خریدها با سقف ۰٫۳٪ بالای بهترین فروش؛ باقی‌ماندهٔ پرنشده پس از ۶۰ ثانیه لغو می‌شود.
- اجرای واقعی فعلاً فقط بازارهای تومانی را معامله می‌کند.
- دو کلید توقف سراسری در بک‌آفیس: «معامله با پول واقعی» (هیچ سفارش واقعی) و «ورودهای جدید» (فقط مدیریت خروج).

## استقرار روی رانفلر (اپ جدا از Nova)

1. `python scripts/package_algorithmic.py` فایل `dist/algorithmic-runflare-v1.0.0.zip` را می‌سازد (Dockerfile در ریشه).
2. یک اپ جدید در رانفلر با یک PostgreSQL (می‌تواند همان سرور Nova باشد؛ فضای `algorithmic` جداست) و یک دیسک برای `/data`.
3. متغیرهای محیطی:

| متغیر | مقدار |
| --- | --- |
| `ALGO_ORIGIN` | آدرس عمومی، مثلاً `https://algorithmic-trade.ir` |
| `ALGO_VAULT_KEY` | کلید Fernet (`python -c "from cryptography.fernet import Fernet;print(Fernet.generate_key().decode())"`)؛ گم شود، کلیدهای ذخیره‌شده قابل بازگشایی نیستند |
| `ALGO_ADMIN_PHONES` | شماره‌های ادمین اولیه، جدا با کاما |
| `SW_DATABASE_URL` | آدرس PostgreSQL |
| `SW_DB_NAMESPACE` | `algorithmic` (پیش‌فرض Dockerfile) |
| `PORT` | پورتی که در رانفلر انتخاب کرده‌اید، مثلاً `8000` |
| `ALGO_SMS_API_KEY` | کلید API پنل IPPanel (برای اولین ورود ادمین لازم است) |
| `ALGO_SMS_SENDER` | شمارهٔ فرستنده، مثلاً `+983000505` |

هر تنظیم بک‌آفیس را می‌توان با متغیر محیطی `ALGO_` + نام تنظیم با حروف بزرگ و `_` به‌جای نقطه هم داد (مثلاً `sms.pattern_code` ← `ALGO_SMS_PATTERN_CODE`). مقداری که در بک‌آفیس ذخیره شود بر متغیر محیطی مقدم است.

4. با شمارهٔ ادمین وارد شوید؛ در «بک‌آفیس ← تنظیمات»: کلید API و شمارهٔ فرستندهٔ IPPanel، مرچنت زرین‌پال (و خاموش کردن sandbox هنگام واقعی شدن)، کلید LLM پلتفرم. «ارسال پیامک آزمایشی» را بزنید.
5. پلن‌ها را در «بک‌آفیس ← پلن‌ها» تنظیم کنید (پیش‌فرض: رایگان، حرفه‌ای، ویژه).

اجرای محلی: `ALGO_ENV=development ALGO_VAULT_KEY=... ALGO_ADMIN_PHONES=0912... PORT=8090 python -m algo.serve` (در حالت توسعه اگر پیامک تنظیم نباشد کد روی صفحه نشان داده می‌شود) و در پنجرهٔ دیگر `python -m algo.runner`.

## آزمون‌ها

`python -m unittest tests.test_algorithmic` — ورود و محدودیت‌ها، ادمین و CSRF، رمزنگاری تنظیمات، شکل درخواست IPPanel، پرداخت یک‌باره، چرخهٔ ربات و تأیید، اجرای آزمایشی، سفارش نامعلوم، نردبان TP، کلیدهای توقف و مجوز نوشتن.
